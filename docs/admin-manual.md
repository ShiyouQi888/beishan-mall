## 一、登录与界面

### 1.1 登录

打开 `/admin/` 会进入登录页，输入**登录账号 + 密码**即可。

- 账号密码由环境变量预置：`ADMIN_USER`（默认 `admin1`）、`ADMIN_PASSWORD`（默认 `123456`）
- **首次启动自动创建**；账号已存在时**不会**用环境变量覆盖密码，所以后台改过的密码不会被重启刷掉
- 忘记密码：把 `ADMIN_PASSWORD_RESET` 设成 `1` 重启一次，密码会强制改回 `ADMIN_PASSWORD`，改完记得设回 `0`
- 登录态有效期 12 小时，过期后自动回到登录页

> **改了环境变量还是登不上？** 先看容器日志里 `[admin]` 开头的那行，它会直接告诉你这次生效的是哪个账号：
> `[admin] 已创建内置管理员 admin，密码取自环境变量 ADMIN_PASSWORD；库里原有管理员：admin1（仍然可用）`
> 另外 `docker compose restart` **不会**重读 `.env`，必须 `docker compose up -d` 让容器重建。

### 1.2 修改自己的登录密码

右上角用户名旁边点「修改密码」，填原密码 + 新密码（6–32 位，两次一致）即可。

- 任何管理员都能改**自己**的密码，不需要权限节点
- 改完当前会话不会被踢出，**下次登录**用新密码
- 如果是给别人重置密码，走「权限管理 → 管理员」，编辑该账号直接填新密码

### 1.3 界面结构

| 区域 | 说明 |
|---|---|
| 左侧栏 | 8 个分组、32 个菜单项。菜单按当前账号权限下发，没权限的不会显示 |
| 顶部栏 | 当前页面路径、账号名、**修改密码**、访问商城、退出登录 |
| 主区域 | 列表页 / 表单页 / 配置页 |

侧边栏左下角可折叠，折叠后只剩图标，方便小屏操作。

## 二、列表页的通用操作

后台 18 个数据模块共用同一套列表页，操作方式统一：

| 操作 | 说明 |
|---|---|
| **搜索** | 顶部搜索框，按该模块支持的关键字段模糊匹配（如商品按名称/编号） |
| **筛选** | 部分字段（下拉、开关、金额、数字）可直接作为筛选条件，选中即生效 |
| **新增** | 右上角「+ 新增XX」，弹出表单 |
| **编辑** | 行尾「编辑」，修改后点「保存」 |
| **删除** | 行尾「删除」，**业务记录（订单、会员、资金流水、提现、结算、实名）不允许删除**，系统会拦下 |
| **分页** | 底部分页器，单页最多 100 条 |
| **列设置** | 部分页面支持隐藏/显示列，用于精简视图 |

> 保存前系统会做后端校验（必填、格式、唯一性），失败会以红色提示返回，**不会静默失败**。

## 三、权限模型

后台权限是**菜单级**的，粒度到「能不能看到某个菜单」，不做按钮级控制。

- **角色** → 绑定一组菜单节点；**管理员** → 绑定一个角色
- 登录后服务端按角色过滤菜单再下发，**没权限的菜单前端拿不到**，直接调接口也会被拒（403）
- 超级管理员（角色 ID 6）**默认拥有全部权限，且不可被修改**
- 角色权限在「权限管理 → 角色管理 → 分配权限」里勾选，支持分组半选

默认两个角色：

| 角色 | 说明 |
|---|---|
| 6 超级管理员 | 全部权限，不可配置 |
| 7 运营 | 需手动分配权限，适合日常运营人员 |

## 五、产品管理

### 5.1 商品管理

列表顶部有统计卡片（在售/下架数量）。这是本系统的主战场——**商品在会员之间流转，而不是从仓库发货**。

> **抢购商品与商城商品已合并**：现在只有一套「商品管理」，不再有「商城商品」菜单。
> 一件商品属于哪些场次，**不在商品里设置**，而是去「抢购场次 → 配置 → 关联商品」维护；
> 同一件商品可以同时关联多个场次。一件场次都没关联的商品，相当于首页/分类里随时可买的普通商品，
> 不受场次时段限制（原来的「商城商品」语义）。

**核心概念：商品归属于某个「持有人」**

- 商品不是"库存"，而是**某个会员名下的标的物**（`持有人` 字段）
- 会员抢到后，持有人变成他；他再转拍，商品落到**下一场**等待下一位
- `流转次数` 记录这件商品被成交过几次

**新增/编辑字段**

| 字段 | 说明 |
|---|---|
| 商品名称 | 必填，展示用 |
| 商品编号 | 用于搜索与对账 |
| 商品图 | 列表与 H5 展示的主图。可从「文件管理」里选已有图片，不用重复上传 |
| 关联场次 | **只读**。显示这件商品目前挂在哪些场次（可能多个），去场次页「关联商品」改 |
| 场次日期 | 只读。转拍进下一场时自动写入，空 = 不限日期 |
| 商品分类 | 归属分类，影响 H5 分类页与首页筛选 |
| 持有人 | 当前归属会员。**置 0 表示平台持仓** |
| 现价 | 当前标价（`goods_min_price`）。转拍时会自动按涨价率更新 |
| 划线价 | 展示用的原价，需高于现价 |
| 基准价 | 色块水位从它起算，默认取首次上架时的现价；转拍不会改它 |
| 价格上限(元) | 填**金额**不是百分比：这件货最高能卖到多少钱。填 1200 = 涨到 1200 就封顶；0 = 不限。到顶后价格锁死，并且不能再转拍 |
| 库存 | 普通单件商品填 1；一批货填总件数，抢一个减一个，卖光自动下架 |
| 流转次数 | 已成交次数，一般不用手改 |
| 实际销量 | 累计成交件数 |
| 排序 | 数值越小越靠前 |
| 状态 | 上架 / 下架 |
| 详情 | 富文本，H5 商品详情页展示 |
| 图片集 | 详情轮播图，可多选；同样支持从「文件管理」选取 |

**价格水位（色块预警）**

列表里有一列「价格水位」，用一根**绿 → 黄 → 红**的色标显示当前价在「基准价 → 价格上限」这段区间里的位置，白点是当前位置：

| 颜色 | 含义 |
|---|---|
| 绿 | 水位 < 35%（离上限还远），安全 |
| 黄 | 35% ~ 70%，开始留意 |
| 橙 | > 70%，接近上限 |
| 红 + 「已达上限」 | 价格已封顶，**不能再转拍** |
| 灰字「未设上限」 | 该商品没配上限，价格随涨价率一直走 |

> 新建商品时**不需要选场次**，建好之后到场次页关联即可。
> 列表工具栏的「关联场次」下拉可以按场次筛选商品，它查的是关联表，不是商品表字段。

**商品状态字典**

| 值 | 含义 | 进入方式 |
|---|---|---|
| 10 上架 | 可被抢购 | 手工上架 / 转拍后自动上架 |
| 20 下架 | 不参与流通 | 手工下架 / 平台回收后自动下架 / **场次到期自动下架** |

### 5.2 关联商品（在场次里维护）

商品页没有「场次」字段，**本场卖什么由「抢购场次 → 配置 → 关联商品」决定**（`specialarea_goods` 关联表，多对多）。

| 操作 | 说明 |
|---|---|
| + 关联商品 | 弹窗里按名称/编码搜索并勾选，可一次加多件；已在本场的商品不可重复勾选 |
| 移除 | 只解除关联，商品本身不删除、也不下架 |
| 其它场次 | 关联列表里显示这件商品还挂在哪些场（一件商品可同时挂多个场次） |
| 商品数 | 场次列表上的数字 = 本场已关联的件数 |

- 商品**一件场次都没关联**时，不受场次时段限制，在首页/分类/搜索里随时可买（原「商城商品」口径）
- **转拍**时商品会被排到下一场，并只保留「下一场」这一条关联 —— 避免旧场次里还能按旧价再抢一次
- 场次删掉时，关联一并清除，商品保留

### 5.3 商品分类

| 字段 | 说明 |
|---|---|
| 分类名称 | 必填，H5 分类页与首页 tab 展示 |
| 分类图标 | 可用内置图标（`icon:xxx`），也可上传自定义图 |
| 首页显示 | 显示 / 隐藏。隐藏后这个分类**不出现在 H5 首页分类栏**，但分类页里还在 |
| 类型 | 2 = 商城分类（默认） |
| 排序 | 越小越靠前 |

> 分类图标支持内置 SVG 图标库，比上传图片更清晰、加载更快。

**批量开关首页显示**

列表页「查询」按钮右侧有两个批量按钮，只作用于**抢购分类**（商城分类不受影响）：

| 按钮 | 效果 |
|---|---|
| 全部上首页 | 所有分类的「首页显示」置为显示 |
| 关闭全部分类 | 所有分类置为隐藏 —— 首页分类栏随之整条消失 |

分类全部隐藏后，H5 首页**不再渲染分类栏**（连「全部」这个标签也不会留），商品瀑布流直接接在服务承诺条下面。
单条分类栏的整体开关仍在「系统设置 → 导航配置 → 首页商品分类」，两个入口效果一致。

### 5.4 抢购场次

场次决定"什么时候能抢"。本系统按天分多个场次（如上午场/下午场/晚间场）。

| 字段 | 说明 |
|---|---|
| 主标题 | 必填，如「晚间场 · 珍藏专场」 |
| 副标题 | H5 场次卡片上的卖点文案 |
| 场次图 | 场次卡片配图 |
| 开放日期 | 周一到周日多选，决定这个场次每周哪几天开放 |
| 开始/结束时间 | 每日开放时段，用时间选择器选（如 08:00 ~ 12:00）；结束留空=不限时 |
| 限购次数 | 每人每场最多买几件 |
| 转拍时限(小时) | 成交后建议多少小时内转拍；超时仍可转拍，但订单动态会记一笔「超时挂牌」 |
| 开放预约 | 是否允许提前预约 |
| 启用 | 停用后该场次不对外 |
| 排序 | 场次顺序的兜底依据（见下方说明），越小越靠前 |

**场次顺序**：先按「此刻的状态」分三档，再按时间排：

| 档 | 说明 |
|---|---|
| 1 | **进行中**——今天开放且当前时刻在时段内 |
| 2 | **未开始**——今天开放但还没到开始时间 |
| 3 | **已结束 / 今天不开放**——沉到最后 |

同档内依次比较：各场次开始时间 → 场次标识语义（`forenoon` 上午 → `afternoon` 下午 → `evening` 晚上）→ 排序值。

比如下午 3 点看首页：下午场排第一（进行中），晚间场第二（未开始），上午场沉到最后（已结束）。

**商品在场次之间怎么流转**

| 时机 | 发生什么 |
|---|---|
| 被抢下并付款 | 商品**立即下架**，不再出现在任何场次，别人无法按原价再抢；商品进入买家的「我的店铺」，标记「待转拍」 |
| 买家转拍上架 | 标价按涨价率上调，商品重新上架，并**自动进入下一个场次**（上午 → 下午 → 晚上 → 回到上午） |
| 一直不转拍 | 商品保持下架，只在该持有人「我的店铺」里可见 |

> 落场次时只考虑**启用中**的场次，停用的会跳过。

场次有两个入口，分工不同：

| 入口 | 覆盖字段 |
|---|---|
| **配置** | 运营最常改的：限购数量、转拍时限、场次主标题与配图 |
| **编辑** | 通用表单，覆盖全部字段：副标题、排序、启用、开放预约等 |

> 改活动设置用「配置」更快；改副标题/排序/启用状态用「编辑」。

**专场配置**（点行尾「配置」进入）

这是场次的扩展设置页，包含：

- **开放日期 + 抢购时段**：星期多选 + 时间选择器，每个场次各配各的
- 限购数量、转拍时限
- 场次主标题与配图上传（图片建议 ≤ 2 MB）
- **关联商品**：本场卖哪些货。点「+ 关联商品」搜索勾选即可，弹窗里能看到商品是否已在本场、还挂在哪些其它场次；表格每行可「移除」（只解除关联，不删商品）

> 每个场次按自己的「开放日期 + 时段」开放；过了时段，即使商品还在架也抢不了（跨天时段不支持，请拆成两个场次）。

### 5.5 关于「转拍涨价」

标价不是由会员手填的，而是**服务端按后台配置自动计算**：

```
下一轮标价 = 上一手成交价 × (1 + 转拍涨价率)
例：10000 → 10300 → 10609 → 10927.27（逐轮复利）
```

- 涨价率在「系统设置 → 交易设置 → 转拍涨价率(%)」里配，默认 3%
- 涨价率 > 0 时，**前端传入的价格一律忽略**（防篡改）
- 涨价率设为 0 则退回按原价挂牌
- **到顶判定看「下一轮会不会越界」**：上限 1200、当前 1180、涨 3% 会到 1215 → 当场判到顶，不再允许挂出（不会出现「削到 1200 再停」那一轮）；
  已经在上限上的商品，报价接口和转拍接口都会拒绝，会员端「我的店铺」会显示「已达价格上限，不能再转拍」

## 六、订单管理

### 6.1 订单类型与状态

**类型**

| 值 | 名称 | 说明 |
|---|---|---|
| 1 | 抢购订单 | 场次内抢购产生，走流转模型 |
| 2 | 寄卖订单 | **历史数据**，新版已不再产生（挂单信息改为记在原订单上） |
| 3 | 商城订单 | 普通电商下单 |
| 4 | 寄买订单 | 后台代为创建 |

**状态**

| 值 | 名称 | 下一步 |
|---|---|---|
| 0 | 待付款 | 可「取消」，或等用户付款 / 后台「确认收款」 |
| 10 | 待发货 | 可「发货」 |
| 20 | 待收货 | 等用户「确认收货」 |
| 30 | 已完成 | 终态 |
| 40 | 已取消 | 终态 |

### 6.2 全部订单

列表字段：订单号、商品图/名称、类型、单价、数量、总额、服务费、状态、支付方式、买家、卖家、快递单号、下单时间。

**行操作**

| 按钮 | 出现条件 | 作用 |
|---|---|---|
| 查看 | 始终 | 打开订单详情 |
| 发货 | 状态=待发货 | 填快递公司 + 单号，状态转 20 |
| 确认收款 | 状态=待付款 且 线下凭证支付 | 确认已收到转账，状态转 10 |
| 审核 / 拒绝 | 待审核订单 | 审核通过或拒绝 |
| 取消 | 状态=待付款 | 关闭订单，状态转 40 |
| 补发直推奖 | 已支付 | 该笔订单漏发直推奖时手动补发（**同一订单不会重复发放**） |
| 团队订单 | 始终 | 查看买家所在团队的订单 |

**顶部工具**

| 按钮 | 作用 |
|---|---|
| 批量导入 | 按行批量创建订单，失败行会逐条返回原因（如「商品不存在」） |
| 新建寄买单 | 指定商品 + 会员 + 价格，代为创建一笔寄买订单 |

**批量确认收款**：会员线下转账后，列表里是一笔一笔待确认的。
勾选多笔 → 点「批量确认收款」→ 一次入账，不用逐单点。

系统逐笔处理并如实回报：能确认的确认，已确认过的跳过，提示会写成「已确认 3 笔，1 笔跳过」，
不会假装全部成功。每笔照样会写订单日志、扣减库存、触发结算。

### 6.3 系统回收

商品涨到「价格上限」后，持有人已经无法再转拍（价格会突破上限），这件货就等于砸在手里。
系统会**自动回收结算**：按商品「当前实际价格」接盘（刚买下的按买入价原价退回；已挂牌的按挂牌价），商品转平台持仓。

| 列 | 说明 |
|---|---|
| 买入价 | 持有人当初成交的价格 |
| 回收价 | 结算给持有人的金额 = 买入价 ×(1 + 转拍涨价率) |
| 持有人收益 | 回收价 − 买入价（平台承担） |
| 状态 | **已结算**（钱已到账）/ **待处理**（开关关闭或超出每日上限，未打款） |
| 回收价 | 商品当时的实际价格（刚买下按买入价，已挂牌按挂牌价） |

- **回收后彻底下架**：商品打上「封顶」标记，抢购/首页/分类/搜索/详情全部不再出现，与原持有人再无关系
- **二次上架**：商品行 →「编辑」把状态改回「上架」，系统自动解封顶并把基准价重置为当前售价，前台才会重新出现（不改状态就永远不出现）
- **全自动**：服务端每 60 秒自动扫描一次，本页列表每 20 秒自动刷新，不需要点任何按钮
- **新回收有提醒**：会弹出「系统回收提醒」并语音播报商品与金额；语音开关在右上角「消息」面板里
- **待处理** 行有「立即结算」按钮，确认后按记录金额补结算
- 结算后商品归平台（持有人 0）、下架、退出场次，可在「商品管理」里改回上架重新流通
- 成本闸门在「系统设置 → 交易设置」：**到顶自动回收** 开关与 **每日回收上限(元)**
- 到顶即回收：**挂牌中和已下架都算**（继续挂着只会等来一个「买下就卡死」的接盘人）
- 还没到顶不回收；同一商品已结算过不再回收
- **缺买入订单**（后台指派/历史数据）的：只记「待处理」不打款，核对金额后手动结算

## 七、财务中心

### 7.1 财务大盘

一个页面看清「每天赚了多少、钱在哪、哪里会出问题」。进入「财务中心 → 财务大盘」。

**顶部四张主卡**

| 卡片 | 含义 |
|---|---|
| 今日经营净利 | 今天的收入减去今天的奖励支出 |
| 本月经营净利 | 本月累计，括号里是订单数与成交额 |
| 累计经营净利 | 有史以来的总账 |
| 会员负债 | 全体会员余额 + 可提现佣金，即平台随时要兑付的钱 |

**第二排四张辅卡**

| 卡片 | 含义 |
|---|---|
| 累计现金净流 | 经营净利 − 平台回收支出。为负说明在垫钱囤货 |
| 待审核提现 | 已经冻结、等待打款的钱 |
| 单均毛利 | 抢单服务费 − 直推奖，每单真正留下的百分点 |

**口径（点右上「口径说明」可随时查）**

```
经营收入 = 抢单服务费（买家额外付的）+ 转拍上架费
经营支出 = 直推奖
经营净利 = 收入 − 支出
平台回收支出 = 平台接盘付出的钱（到顶系统回收，钱换货，不计入损益，单列）
现金净流 = 经营净利 − 平台回收支出
会员负债 = 会员余额合计 + 可提现佣金合计
```

> 注意：**商品成交额（GMV）不是平台的收入**。平台赚的是服务费与上架费，成交额只用来衡量规模。

**风险与异常**

系统会自动比对配置与实际数据，按 `高风险 / 关注 / 提示 / 正常` 四级给结论：

| 触发条件 | 等级 | 处理建议 |
|---|---|---|
| 单均毛利 ≤ 0（服务费 ≤ 直推奖） | 高 | 每单都在亏，立刻调价 |
| 单均毛利 < 1% | 关注 | 利润太薄，一单坏账吃掉多单利润 |
| 累计经营净利为负 | 高 | 支出超过收入，查奖励比例与异常补发 |
| 现金净流为负 | 关注 | 回收压现金，确认回收商品能否再卖出 |
| 分销成本占收入 > 60% | 关注 | 赚的钱大半发给了推广 |
| 平台回收占成交额 > 20% | 关注 | 商品流转不畅，查涨幅与场次人气 |
| 有会员余额为负 | 高 | 账务异常，人工核账 |
| 待审核提现 > 0 | 提示 | 预留资金 |
| 未确认的匹配付款单 > 0 | 提示 | 确认后账目才算结清 |

全部正常时只显示一条「暂无异常」。

**两个趋势**

- **近 30 日经营净利**：柱状图，红柱=盈利、绿柱=亏损，中线是 0。鼠标悬停看当天明细。
- **近 6 个月经营明细**：表格列出订单数、成交额、服务费、上架费、经营收入、直推奖、经营净利。

**日常用法**：每天开店先看「今日经营净利」有没有异常波动，再看风险列表；每周对一次「会员负债」与「累计现金净流」的差，判断是否需要备付金。

### 7.3 佣金记录

会员的佣金与资金流水（`finance_energy`）。

| 类型 | 含义 |
|---|---|
| 2 | 余额变动（成交收款、提现、上架费、平台回收、调账等） |
| 3 | 返佣（直推奖） |

字段：会员、金额、类型、名称、备注、时间。**这是对账的第一手依据**。

### 7.4 提现审核

| 字段 | 说明 |
|---|---|
| 会员 | 申请人 |
| 金额 / 手续费 / 实到 | 申请金额、按费率算的手续费、实际到账 |
| 收款账户 | 会员选择的卡 |
| 状态 | 0 待审核 / 10 已通过 / 20 已拒绝 |

**批量审核**：勾选多笔 → 「批量通过」或「批量驳回」。
驳回会把金额原路退回会员余额并记流水；通过不会退，钱要靠你线下打款。
同样逐笔处理、如实回报（如「已通过 5 笔，1 笔跳过」）。

**审核**

- 通过：状态转 10，款项状态按线下打款处理
- 拒绝：状态转 20，**申请金额自动退回会员余额**，并记一条「提现驳回退回」流水

> 会员提交提现时余额已经**立即冻结扣减**，所以驳回必须走审核动作，不能手工加余额。

**分销规则（一级）**

分销只有一级：**A 推荐 B，B 之后所有成交的直推奖都归 A**，与 B 的下线无关。

- 绑定关系在注册时确定（填邀请码即绑定），**终身有效**，会员自己无法修改
- 后台可在「会员列表 → 编辑 → 上级」里改绑；改绑后立刻生效，**后续成交的佣金发给新上级**
- 改绑会自动重算该会员及其下级的层级路径（`path` / `level`），并同步新旧上级的直推名单
- 禁止把会员挂到自己的团队下（防环）
- 无平级奖：本系统不采用级差制，不存在"上级与下级同级导致差额为零"的问题

| 每日回收上限(元) | 0（不限） | 平台每天最多垫付的回收款；超出后当天的到顶商品转为待处理 |

> **抢购时间不在交易设置里**：每个场次各有自己的「开放日期 + 每日时段」，去「抢购场次」里配（见 5.4）。

**当前经济模型（以 10000 元商品、上架费 0% 为例）**

```
买家实付    10200   （标价 10000 + 服务费 200）
卖家到账    10000   （货款全额，平台不抽成）
平台留        200   （服务费）
  ├─ 50   → 买家上级（直推奖 0.5%）
  └─ 150  → 平台净收（1.5%）

下一轮标价  10300   （+3%），上架费 0，持有人净赚 300
```

**把上架费调回 2.8% 之后（下单时一并收取）**

```
买家实付    10480   （标价 10000 + 服务费 200 + 上架费 280）
下一轮标价  10300   （+3%）
持有人净赚   −180   （10300 − 10480）
平台收入      480   （200 服务费 + 280 上架费）
```

> 结论：上架费一旦开启，涨价率必须高于「服务费 + 上架费率」才有净收益。
> 例如 2% + 2.8% = 4.8%，涨价率至少要 5% 以上，否则每转一手都在亏钱，
> 会员会在「我的店铺」看到负数收益（系统如实展示，不会粉饰）。

### 10.9 数据清除

给**真人全量测试**用的清库工具：把测试过程产生的订单、资金、会员清掉，回到干净起点。
入口在「系统设置 → 数据清除」。

> **删除后无法撤销。** 每次执行前系统会先把数据库备份到 `server/data/backup/`，真出问题可以拿备份回滚。

**谁能用**

默认**只有超级管理员**。要交给别人，去「权限管理 → 角色管理」，把「系统设置 → 数据清除」这个节点
勾给对应角色即可（同其它权限节点的下放方式）。

**四个清除范围**

| 范围 | 会删什么 | 注意 |
|---|---|---|
| 订单与资金 | 订单、订单日志、资金流水、提现、结算账目、回收台账 | 最常用 |
| 会员与团队 | 除官方账号外的全部会员，及其地址、收款卡、实名、站内消息 | **必须同时勾选「订单与资金」**，否则订单会变成指向不存在会员的孤儿数据，系统会直接拒绝 |
| 商品复位 | 商品不删除，只把持有人改回官方、流转次数与销量归零、全部重新上架 | 商品图片、价格、分类都不动 |
| 未引用的素材 | 只删没人用的图片，商品/广告/配置正在用的会保留 | 相当于素材库的一次瘦身 |

**永远不受影响的东西**

后台账号、角色与权限节点、系统设置（全部配置）、商品分类、抢购场次、商品本身（只复位不删）、
广告、导航、公告、运费模板、官方账号。

这些清掉之后页面会直接打不开，所以代码里写死了不碰。

**操作流程**

1. 勾选范围（右侧会实时显示每个范围影响多少行）
2. 点「清除选中数据」
3. 弹窗里核对风险清单
4. 点「一键复制」拿到确认语，粘贴到输入框（**必须一字不差**，否则确认按钮是灰的）
5. 点「确认清除」

**执行后**

- 官方账号保留并复位：`13800000001`（邀请码 `boss01`，余额/佣金/积分归零）
- 商品全部回到官方名下并重新上架
- 自增 id 归零，下一个注册用户是 `member_id = 2`，下一笔订单是 `order_id = 1`
- 页面底部会显示本次清除行数和备份文件名

## 十二、常见业务 SOP

### SOP 1：开一场新的抢购活动

1. **商品分类** → 新增分类（若已有可跳过）
2. **抢购场次** → 新增场次：填主标题、场次图、限购次数、转拍时限（开放时间在交易设置里统一设一次）
3. **抢购商品** → 新增商品：选场次、分类、持有人、现价、状态设为上架
4. 到 H5 验证：场次时间内能在抢购页看到该商品

### SOP 2：处理一笔待发货订单

1. 控制面板看「待发货订单」→ 点进去
2. 核对买家与商品
3. 点「发货」，填快递公司与单号
4. 状态自动转为待收货，会员可在 H5 确认收货

### SOP 3：线下凭证订单确认收款

1. 会员转账后上传凭证，订单状态仍是「待付款」
2. 订单行点「确认收款」
3. 系统标记已支付，货款结算给卖家，状态转待发货

### SOP 4：场次到期没卖掉的货

不需要人工处理：转拍挂出的商品，所在场次结束仍无人买，系统每 5 分钟会自动把它**下架退回持有人**，
并给持有人发一条站内消息；持有人重新转拍即可再次挂出。

商品到顶（下一轮涨价会越过上限）另有一套流程：由平台按「当前实际价格」接盘结算，
见 6.3「系统回收」。

### SOP 5：审核提现

1. 财务中心 → 提现审核
2. 核对金额、手续费、收款账户
3. 通过 → 线下打款后点「通过」；拒绝 → 填原因点「拒绝」（金额自动退回会员余额）

### SOP 6：核账

1. 财务中心 → 财务大盘：看今日/本月/累计的经营收入、支出、净利与风险提示
2. 财务中心 → 结算账目：按订单核对整单资金结算记录

> 会员之间不再互相打款：成交即入账（买家付款时卖家当场到账），所以没有「差价匹配」这一步。

### SOP 7：审核实名

1. 会员管理 → 实名认证
2. 核对姓名与身份证号是否一致、图片是否清晰
3. 通过 → 会员可参与抢购与提现

### SOP 8：给会员手工调账

1. 会员管理 → 会员列表 → 行尾「调账」
2. 填增减金额，**必须写备注**（如「活动补偿」）
3. 保存后余额立即变动，并生成一条资金流水

> 调账是敏感操作，备注会永久留在流水里，请写清楚原因。

### SOP 9：新增一个受限运营账号

1. 权限管理 → 角色管理 → 新增角色（如「商品运营」）
2. 点「分配权限」，只勾选「产品管理」等需要的菜单
3. 权限管理 → 管理员 → 新增账号，选该角色
4. 用新账号登录验证：应只看到被授权的菜单

## 十四、装到手机桌面（PWA）

H5 商城是 PWA，会员可以把它「添加到桌面」，之后像 App 一样点开就用，不用每次输网址。

### 14.1 会员怎么操作

| 浏览器 | 操作 |
|---|---|
| Android（Chrome / 系统浏览器） | 打开首页，底部会出现「把 XX 添加到桌面」提示，点「添加」即可。也可以走浏览器菜单 →「安装应用 / 添加到主屏幕」 |
| iPhone / iPad（Safari） | 点底部「分享」按钮 →「添加到主屏幕」→ 确认。页面里也有「怎么加」的图文引导 |
| 微信里打开 | 微信不支持直接添加，需点右上角「···」→「在浏览器打开」，再按上面步骤 |

提示条 7 天内不重复打扰；装好之后从桌面图标进入，是全屏独立窗口（没有浏览器地址栏）。

### 14.2 后台会跟着变什么

- 桌面图标名称 = 「商城设置 → 商城名称」
- 图标配色跟随「商城设置 → 外观主题」（三套主题各有一套 192/512/遮罩版/iOS 180 图标）
- 若「商城 Logo」有上传，会额外作为一张图标提供给系统挑选

### 14.3 部署注意

- **必须 HTTPS**（或 localhost）。用 http 打开时浏览器不会给安装提示，Service Worker 也不会注册
- 反向代理直接转发即可，不需要额外配置 MIME：清单由服务端动态生成，返回 `application/manifest+json`
- 断网时只兜底首页外壳，接口数据仍需要网络；Service Worker 不缓存 `/api`、`/uploads`、`/admin`


## 十五、常见问题

**Q：会员反馈抢不到商品，提示"不在抢购时间内"？**
先看「抢购场次」里该商品的**所属场次**：开放日期是否包含今天、开始/结束时间是否覆盖当前时刻。每个场次各管各的时段，跨天无效（23:00-02:00 这种写不了，要拆成两个场次）。
再确认商品是否归属该场次、场次是否启用。

**Q：会员违规了，删掉还是禁用？**
用**禁用**。禁用会立刻阻断登录与所有操作（包括已登录的会话），可随时恢复；
删除只适用于从未产生过任何数据的账号——有订单、流水、提现或下级的账号系统会拒绝删除，
因为删了会让订单和资金记录变成孤儿数据，对不上账。

**Q：禁用后会员还能下单吗？**
不能。后端在登录和每一次请求都会校验账号状态，禁用后旧 token 立即失效。

**Q：会员违规了，删掉还是禁用？**
用**禁用**。禁用会立刻阻断登录与所有操作（包括已登录的会话），可随时恢复；
删除只适用于从未产生过任何数据的账号——有订单、流水、提现或下级的账号系统会拒绝删除，
因为删了会让订单和资金记录变成孤儿数据，对不上账。

**Q：禁用后会员还能下单吗？**
不能。后端在登录和每一次请求都会校验账号状态，禁用后旧 token 立即失效。

**Q：想放开注册、不让邀请码卡住新用户？**
到「交易设置 → 注册必须填邀请码」关闭即可。关闭后 H5 注册页的邀请码会变成「选填」，
不填也能注册，该会员为根节点（无上级）；但只要填了就必须有效，填错仍会提示"邀请码不存在"。

**Q：会员点转拍提示"您不是该商品持有人"？**
商品的「持有人」字段与订单不符。常见于手工改过商品归属，需在抢购商品里核对。

**Q：为什么转拍价格不能手填了？**
涨价改为服务端计算，前端价格被忽略，防止篡改。要调整价格只能改「转拍涨价率」。

**Q：上架费填 0 后，会员流水里没有上架费记录了？**
这是预期行为。费率为 0 时不收、也不写 0 元流水，避免污染流水列表。

**Q：上架费为什么在会员抢购时就收了，而不是等转拍？**
原来是转拍时才从余额扣。问题是那时货已经在会员手上、钱也付过了——余额不够就转不了拍，
货卡在手里，运营只能手工调账；而且会员在掏钱那一刻并不知道有这笔费用。
现在改成下单时随货款一起算清（确认订单页会单独列出），转拍时不再扣款，
「我的店铺」和转拍弹窗都会标注「上架费（下单时已付）」。

**Q：会员买了货但一直没转拍，上架费退吗？**
不退。这笔钱在下单时就已计入实付，属于「获得转拍资格」的预付费用。
如需补偿，走「会员管理 → 余额调整」手工处理，并备注原因。

**Q：上架费改成预付后，老订单的收益怎么算？**
老订单（下单时没预付过）仍按原方式在转拍时从余额扣，
两种订单的「实际成本」都等于「货款 + 服务费 + 上架费」，所以净收益口径一致。
回收台账的「实际成本」也已同步包含上架费。

**Q：某个运营账号登录后菜单是空的？**
该账号的角色没有分配任何菜单节点。到「角色管理 → 分配权限」勾选后，让他重新登录。

**Q：订单能删除吗？**
不能。订单、会员、资金流水、提现、结算、实名都属于审计记录，只能改状态不能删。

**Q：平台回收后商品去哪了？**
持有人变成 0（平台持仓），状态变下架，并打上「封顶」标记、前台不再展示。到「商品管理」编辑并把状态改回上架才会重新流通。

**Q：改了设置没生效？**
配置页必须点右上角「保存设置」。保存后前端刷新即生效，无需重启服务。

**Q：会员提现被驳回，钱会自动回来吗？**
会。审核点「拒绝」时系统自动把金额退回余额，并记一条「提现驳回退回」流水。不要手工加余额，否则会重复。
